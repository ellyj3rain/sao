## Record

The operator's chosen target for the dataset's first proposal - the
work words a company deals, record 21's founding example, at a
hundred-plus rows - is authored and landed in the sister repository
as `decisions/work-words.jsonl`: 112 member-rows taken from
`[C83]`'s dump across all six county runs, one row per person per
run, 71 of the dump's one shared population of 187. Each row's
fourth part was written as that person, from the row's own evidence
alone, with the tree's dealing held in a separate file until every
one of the 112 choices was written; the dealing was joined only
afterward, as the `treeDealt` column beside the authored choice, so
the ruling can read one against the other. Of the 58 rows where the
tree dealt a work word, the authored choice took that same word 42
times; 29 rows founded a position the group created and named, in
22 words by 22 persons, five of them founding the same position
under the same word and the same description in more than one
county run. Nothing in the file is intent - rows arrive as a
proposal the operator rules on, and the ruling is the sister's to
record.

## What changed here

the state surfaces every close walks: `PROJECTS.md`'s standing table
and `ROADMAP.md`'s beside-this-tree now say the first rows are in
as a proposal awaiting the ruling; `SESSION_STATE.md` names `[C84]`;
the version machine gains this unit and rolls the patch coordinate;
the thread index classifies the batch.
