### 20260919-through-C120:C81 — Coordination reference source

> C81 supplies a reproducible source family for the first learned coordination
> response experiment. The source catalogue declares twenty synthetic starting
> situations and assigns each independent lineage to train, validation or test
> before execution. It contains no expected response field.

> Each run raises a concrete food-delivery matter, uses Communication and
> Perception to establish actual reception, asks the shipped Controller to
> appraise it, and captures Organization's decision-time evidence before the
> actual return channel. Production forms four each of accept, qualify,
> counter-propose, defer and contest. Every observed response occurs in every
> partition. Decline and withdrawal remain implemented process responses but are
> not represented by this source family.

> Survivors use `SAO.Controller`. Afflicted and Crossed keep distinct pathogen
> audit state while both resolve the retained human shell, current work,
> capability and competing pressure through the registered ZAO adapter and
> `ZAO.Driver`. The task-facing private appraisal carries generic pressure and
> its source owner, not terminal state, diagnosis, diet or another actor's state.
> This preserves their distinct state owners without making either a separate
> controller or treating them as equivalent behavior.

### 20260919-through-C120:C82 — Native coordination shadow

> C82 imports Speakeasy Record 67 at merge commit
> `1e26f90d94720a68285fd9e96bcef016bbcf6e0a`. Its 13,050-byte bundle has
> SHA-256 `02edcdc1caf7489f0871f63e35af2c2cc26966ec74c0cf30eb63d155b1acb33c`.
> The packaged Java reader verifies that exact hash, bundle/schema/compatibility
> identities, tokenizer program, ordered labels, observed support, feature schema,
> FP32 tensors and complete source identities before inference. Missing, corrupt,
> truncated, trailing, non-finite or incompatible artifacts are refused.

> The production Organization appraisal remains authoritative. Only after its
> response revision exists does the Lua owner build the same compact decision-time
> input and 16 typed channels used by Record 66, then submit immutable strings and
> arrays to one low-priority daemon worker. The worker has one thread, a 64-entry
> queue and a 128-request pending ceiling. It returns a prediction and probabilities
> only to the shadow owner; it cannot select, revise or deliver a response and
> cannot create a commitment or work.

> On return, Lua requires the exact bundle and input hashes, response vocabulary,
> probability mask, process and response revisions, canonical input, feature and
> option vectors, durable body owner and the current registered execution-owner
> signature. Stale, foreign, malformed or owner-changed results are retained only
> as bounded withheld observations. World detach or graph bind cancels the Java
> pending map and clears Lua's transient requests and observations. No shadow
> state enters GraphPersistence or save data.
